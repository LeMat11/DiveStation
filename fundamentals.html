C++、Python 与并发

不考语言冷知识，重点考资源、状态和边界

01C++ 的 RAII 解决什么问题？机器人程序里哪里最需要？A

资源获取与对象生命周期绑定：构造成功后对象拥有资源，析构自动释放，异常和早退也不会泄漏。串口/CAN 文件描述符、互斥锁、线程、相机 buffer、GPU 内存最典型。优先用值语义、标准容器和 unique_ptr；共享所有权真的存在时才用 shared_ptr。

02什么时候用线程，什么时候用进程？A

线程共享地址空间、通信便宜，但数据竞争和崩溃传播更难控制；进程隔离故障和依赖，代价是序列化、复制和部署复杂度。高频控制与同进程硬件驱动可能用线程；相机、模型推理或不可信第三方组件常适合独立进程。选择依据是故障域、延迟、数据量和可观测性，不是“线程更快”。

03什么是 data race？加一把大锁为什么通常不够？A

多个执行单元并发访问同一内存，至少一个写且没有正确同步，行为未定义。大锁能临时保证互斥，但可能扩大临界区、阻塞实时循环、形成锁顺序死锁。更好的做法是明确单写者/所有权、不可变快照、消息队列、小临界区和有界等待；共享状态要带时间戳和版本。

04Python 的 GIL 意味着不能做多线程吗？B

不是。GIL 限制单进程中 Python 字节码的 CPU 并行，但 I/O 等待期间会释放，NumPy/OpenCV 等原生扩展也可能释放。网络、串口、相机 I/O 可用线程；CPU 密集纯 Python 用多进程、原生扩展或向量化。还要考虑进程间复制和启动成本。

05如何设计一个线程安全的机器人 SharedState？A

每类数据有明确写入者；写入时更新值、单调时钟时间戳、序列号和有效标志；读者一次拿一致快照，不持锁做 I/O 或计算。控制循环按 age 判断 freshness，不把“最后一个值”默认当成“当前有效值”。高频场景可进一步用双缓冲、原子索引或单生产者/单消费者队列。

06异常、错误码和重试怎么选？B

可恢复、跨层传播的异常在非实时应用层适合用异常；实时/嵌入式热路径常用显式状态和错误码，避免不确定控制流。重试只适用于暂态且幂等的操作，必须有次数、退避和总超时；硬件故障或无效命令不能无限重试，应进入安全状态并保留根因。

Linux、进程与 ROS 2

你的项目未必使用 ROS 2，但机器人岗位通常会检查这些边界

07一个机器人服务“启动了但没工作”，你怎么查？A
  1. 看服务状态、退出码和最近日志；确认实际执行文件、参数、用户和工作目录。
  2. 检查设备节点、权限、组、串口/CAN/相机是否存在且未被占用。
  3. 检查环境变量、配置文件、网络接口与依赖服务。
  4. 手动以前台同一用户启动，保留 stderr；再用最小硬件读写隔离。
  5. 最后才重启整机，因为重启会破坏现场证据。
08什么是单调时钟？为什么控制和超时不能只用系统时间？A

系统/墙上时钟会因 NTP、人工修改或时区变化跳变；单调时钟只向前，适合计算 dt、age、deadline 和 watchdog。墙上时钟适合跨设备日志关联和人类可读时间。工程上常同时记录 monotonic timestamp 与 epoch timestamp，并显式保存时钟映射质量。

09ROS 2 topic、service、action 怎么选？A

Topic 用于连续/异步数据流，如传感器和状态；service 用于短时请求—响应且调用者等待结果；action 用于长任务，需要进度、取消和最终结果。急停不应依赖可能排队的普通 action 路径，应有独立、高优先级、可验证的安全链。

10ROS 2 QoS 最少要理解哪些维度？A

Reliability（可靠/尽力而为）、history/depth（保留多少样本）、durability（晚加入订阅者是否拿历史）、deadline/liveliness（时序与存活契约）。相机通常宁可丢旧帧也不积压；低频配置或地图可能需要可靠与持久。发布/订阅 QoS 不兼容会出现“节点都在但收不到数据”。

11ROS 2 executor 和 callback group 为什么会影响实时性？B

Executor 决定回调何时、在哪个线程执行；耗时回调会阻塞同一执行上下文。Callback group 控制回调能否并发。需要把高频控制、慢服务、日志/视觉分开，避免控制回调里做阻塞 I/O、内存大分配或不可界定的推理。多线程 executor 不是自动线程安全，仍要设计状态所有权。

嵌入式、总线与实时数据

会接线不等于会设计协议和失效行为

12CAN、I²C、UART、SPI 各适合什么场景？A

CAN：多节点、仲裁、差分抗干扰，适合分布式执行器；I²C：板级低速多从设备、两线，但地址与上拉敏感；UART：点对点简单异步流，需自定义 framing；SPI：板级高速、全双工、每从设备片选更多。选择要同时讲距离、带宽、节点数、可靠性、电气环境和软件生态。

13UDP 控制包为什么常加 sequence、timestamp 和 watchdog？A

UDP 低延迟但可能丢包、乱序、重复。sequence 用来检测乱序/缺失，timestamp 判断新鲜度，watchdog 在一定时间没收到有效包时进入安全状态。控制命令最好是幂等的绝对 setpoint；如果必须用增量命令，需要 ACK、去重或更可靠的协议。

14如何估算一条实时链路的延迟预算？A

拆成采样等待、驱动/传输、排队、计算、调度、执行器响应和可能的显示延迟；分别测均值、P95/P99 与最坏情况。更新率不等于延迟：10 Hz 数据仅采样相位就可能带来 0–100 ms 等待。对控制更关心总延迟、抖动和 deadline miss，而不只是平均吞吐。

15watchdog 应该监测“线程活着”还是“数据有效”？A

两者都要但含义不同。心跳能证明执行路径仍在推进，不能证明传感器值更新正确；数据时间戳、序列号、范围和一致性检查才能证明 freshness/validity。安全决策应基于任务需要的数据契约，例如“最近 50 ms 内有递增序列且数值有效”。

16MCU 中断服务函数里为什么不能做太多事？B

ISR 会打断普通任务，长时间执行会增加调度抖动、丢其他中断并破坏实时性。ISR 通常只读必要寄存器、记录时间戳/标志或推入有界队列，把解析、日志和复杂计算交给任务。共享变量要考虑原子性和内存可见性。

17传感器与相机怎样同步？软件时间戳什么时候不够？A

最佳是共同硬件触发或同一硬件时钟；其次是设备时间戳配合 PTP/时钟同步与漂移估计；最后才是主机接收时间。USB/OS 接收时间包含排队与调度抖动，无法代表曝光或采样瞬间。你的压力–PIV 项目可用 Teensy TTL 边沿作为共同 t=0 的实例。

控制、滤波与状态估计

每个算法都要知道假设和失效边界

18PID 三项各做什么？工程实现还有哪些细节？A

P 对当前误差，I 消除稳态偏差但会 windup，D 提供阻尼/预测趋势但放大噪声。工程上需要实际 dt、输出饱和、anti-windup、导数对测量而非 setpoint、导数低通、bumpless transfer、模式切换和限幅。先验证传感器符号、执行器极性和采样频率，再调参数。

19低通滤波为什么会让控制变差？A

滤波降低高频噪声，同时引入相位滞后；截止频率太低会把真实动态也延迟，侵蚀相位裕度，控制器可能更振荡。滤波要围绕传感器噪声频谱、控制带宽和采样率联合设计，并通过 Bode/阶跃或至少延迟测量验证。

20什么是 feedforward？为什么不能替代 feedback？A

Feedforward 根据模型或目标预先给出所需输入，例如重力补偿、摩擦/死区补偿；响应快且不必等误差出现，但对模型误差和扰动无能为力。Feedback 根据误差修正未知变化。常见组合是 feedforward 承担可预测负载，反馈做鲁棒修正。

21互补滤波和 Kalman filter 的区别？B

互补滤波用频段互补的直觉融合，例如陀螺短期稳定、加速度计长期校正，简单易调；Kalman filter 用状态空间模型和噪声协方差递推最小方差估计，并能处理多状态、控制输入和不确定度。KF 并不自动正确：模型、时间同步、坐标和 Q/R 错误会让结果看似平滑但系统性偏差。

22如何处理 actuator saturation、deadzone 和 hysteresis？A

饱和要限幅并做 anti-windup；deadzone 可通过标定 feedforward、最小有效命令或专门模型补偿；hysteresis 需要上下阈值不同的 Schmitt trigger，避免噪声附近抖振。所有补偿必须保留安全限位，并验证跨负载、方向和温度的一致性。

感知、坐标变换与规划

从像素和传感器值一直讲到机器人可用状态

23世界、机器人、传感器坐标系怎样组合？A

刚体变换属于 SE(3)，由旋转 R 和平移 t 组成；点从传感器到世界常写为 pᴡ = Tᴡʙ Tʙˢ pˢ。矩阵乘法顺序不可交换。必须明确变换的方向、坐标约定和时间戳；静态外参和动态位姿不能用不同时间的数据直接组合。

24双目标定的 RMS 很小，为什么深度仍可能不准？A

重投影 RMS 只度量角点模型拟合，不等于全场 metric depth accuracy。误差还来自基线/焦距标定偏差、同步、镜头/温度变化、弱纹理、遮挡、匹配参数和距离平方放大。需要独立距离靶、不同深度/视场位置的验证，以及左右一致性和无效 disparity 过滤。

25BFS、Dijkstra 和 A* 分别什么时候用？A

BFS 用于无权/等权图；Dijkstra 用于非负边权最短路；A* 在 Dijkstra 上加 admissible heuristic 引导搜索，若 h 不高估仍保证最优。机器人中地图分辨率、膨胀半径、动态障碍和重规划频率往往比背模板更重要。

26全局规划和局部控制的职责怎么分？A

全局规划利用较完整地图给出长程可行/低成本路径；局部层根据当前状态、局部障碍和动力学产生短时轨迹或控制命令，并持续重算。接口应包含路径坐标系、时间/速度约束、可行性状态和失败恢复。pure pursuit 是路径跟踪器，不是动态避障规划器。

27传感器 calibration 和 validation 有什么区别？A

Calibration 用已知参考估计模型参数；validation 用未参与拟合的独立数据检查泛化误差。三个点拟合 R² 很高不代表全范围绝对精度高；需要不同位置、方向、负载和温度的独立验证，并区分 precision、resolution、accuracy、repeatability。

安全、测试与系统设计

机器人全栈最能拉开差距的一组题

28设计一条 E-Stop 链路时，什么叫 fail-safe？A

单点故障、软件卡死或通信丢失时系统趋向可接受的安全状态，而不是依赖正常软件路径才能停。物理急停通常应直接切断/禁止危险能量，并有独立反馈；软件 E-Stop 负责协同停车、状态锁存和诊断。恢复必须显式、受控，不能通信一恢复就自动重新动作。

29怎样测试一个涉及真实硬件的控制栈？A
  1. 纯函数/协议单元测试：限幅、状态机、编码解码。
  2. 仿真和 property/invariant 测试：任何输入下不越机械限位。
  3. hardware abstraction + mock/replay：用录制数据复现。
  4. HIL：真实控制器接模拟负载/安全夹具。
  5. 分阶段真机：低功率、无负载、固定装置、完整工况。
  6. 故障注入：断网、传感器冻结、乱序、过温、进程退出，并检查安全状态与日志。
30日志很多但故障仍难查，通常缺了什么？A

缺少共同时间基、请求/命令 ID、状态转换原因、数据年龄、配置版本和结构化字段。日志应记录“为什么改变状态”，而不只是“当前值”。高频数据用有界二进制/JSONL 记录与触发前后 ring buffer，普通日志做事件摘要；避免实时循环同步写磁盘。

31如何设计“相机偶发卡顿但控制不能受影响”的系统？A

相机采集/编码与控制分离线程或进程，通过 latest-frame 有界队列传递；队列满时丢旧帧，不让背压进入控制。控制只消费带时间戳的感知结果并检查 freshness；卡顿时降级为无视觉模式或限制动作。独立监控帧率、age、队列深度、温度和重启次数。

32系统设计题：做一个远程操控水下机器人，你怎样分层？A

输入层产生带序号/时间戳的意图；网络层按命令和视频选择 UDP/WebSocket/可靠通道；机器人侧状态机做控制权仲裁和 watchdog；实时执行层独立频率运行并限幅；传感层各自采集并发布快照；安全层高优先级覆盖普通命令；观测层记录命令、状态、故障和时间同步质量。回答最后给延迟预算、掉线行为与渐进测试计划。

33怎样避免“仿真很好，真机完全不行”？B

先校准接口与基本物理量，再增加模型复杂度；把延迟、噪声、饱和、死区、摩擦、执行器带宽和传感器 dropout 纳入仿真；做参数随机化与灵敏度分析；使用相同控制接口和日志 schema；逐级 HIL/低风险真机验证。sim-to-real 不是单一算法，而是模型、软件接口和验证流程共同决定。

项目表达与行为面

技术深度要通过具体决策和证据表现出来

“介绍一个项目”

90 秒只讲目标、你的职责、系统分层、一个难判断和量化结果。等追问再展开协议和算法。

“最难的 bug”

现象 → 观测证据 → 逐层隔离 → 根因 → 修复 → 防复发。不要把反复试错压缩成“最后发现是接线问题”。

“为什么选这个方案”

需求/约束 → 至少一个备选 → 权衡 → 最终选择 → 怎样验证。主动说出方案牺牲了什么。

“如果重做”

给具体的接口、测试、保护或制造改进，并解释当时没有做的资源与信息约束。

“你和团队的分工”

用“我负责…”说清个人边界，同时说明输入来自谁、交付给谁、如何对齐接口和验收。

“结果不好怎么办”

区分假设失败、实现失败和测量失败；先验证仪器与数据链，再做最小对照和消融，不用调参掩盖结构问题。
