A控制算法、状态机与数据结构11 points
  • Finite state machine：DISENGAGED / LOCKED / OVERRIDE / RAMPING 等显式状态解决摇杆、巡航和自动过渡争夺控制权的问题；状态转换与执行器输出分离。
  • Rising-edge detector：保存上一帧按钮状态，只在 0→1 时触发，避免 50 Hz 轮询下按住按钮重复切换。
  • Hysteresis：巡航接管使用不同进入/退出阈值；热管理为 65/70/75/80°C 分级并设置恢复带，避免阈值附近抖振。
  • Linear interpolation ramp：人工接管释放后 0.3 s 回到 cruise snapshot；退出巡航 2 s 降到安全状态，防止 command discontinuity。
  • Phase accumulator：phase += 2πf·dt；运行中改频率只改变相位推进速度，不改变当前位置。
  • 统一 offset 方程：position = neutral + sign·(amplitude·sin phase + offset)；amplitude=0 时自然退化为静态 hold，不另建模式。
  • Snapshot-and-restore：巡航锁定保存 setpoint snapshot；人工 override 暂时接管，释放后回到保存目标。
  • Ring buffer：Web 日志只保留最近 INFO+ 事件，内存固定，不让长时间运行无限增长。
  • Mixer：把 forward/turn/pitch/yaw 意图映射为左右 motor frequency/amplitude 和镜像 servo angle；共同分量用 sum，对称差动用 difference。
  • Depth-hold 规划：慢速外环 depth error → vertical-velocity target，快速内环 velocity → pitch/actuation；当前未实现，不能当完成能力。
  • Priority chain：E-Stop → armed gate → source ownership → cruise/manual → limit/slew；安全层不能被普通 source mutual exclusion 阻挡。
B软件模块、线程模型与接口8 points
  • Multi-rate threading：motor、controller、CAN receive、IMU、pressure、camera、network、recorder 各按自身周期运行；慢 I/O 不进入 5 ms motor deadline。
  • SharedState + RLock：每个 producer 只写自己的数据块；值与 monotonic timestamp、sequence、valid/error 同步更新；consumer 只在锁内复制 snapshot。
  • Dataclass command structs：命令结构显式包含 motor/servo values、source、timestamp 和 mode，便于追踪“哪个层覆盖了值”。
  • Qt signal/slot：后台线程不直接改 QML；用 signal 把数据 marshal 到 GUI thread。
  • QObject property bridge：Python backend 暴露属性/通知信号，QML 只负责声明式呈现与用户事件。
  • asyncio + FastAPI：REST 做监督/诊断，WebSocket 10 Hz 推送状态；异步连接避免每客户端一个 OS thread。
  • Transport abstraction + callback hook：视频编码/传输实现可替换；capture loop 通过 callback 扩展记录、流式或处理而不硬编码消费者。
  • Config single source of truth：频率、限位、网络、相机和热阈值集中配置；记录时保存配置版本，避免代码中散落 magic number。

D双目几何、数学与信号处理8 points
  • Calibration pipeline：capture checkerboard pairs → sub-pixel corners → monocular calibration → stereo solve → per-pair error → reject outlier → re-solve → export K/D/R/T/P/Q/maps。
  • 质量数字：25 对检测、24 对接受；left RMS 0.196 px、right 0.187 px、stereo 0.246 px、epipolar 0.146 px、baseline 60.566 mm；outlier rejection 使 stereo RMS 从 0.595 降 58.7% 到 0.246。
  • Reprojection error 是角点模型拟合 gate，不是深度 accuracy；epipolar verification 检查 rectified 对应点纵向偏差。
  • StereoSGBM 输出 fixed-point disparity；先做 sign/range validity，再用 Q matrix reproject 到米制 3D。
  • Neighborhood median 比单像素稳定；中心 ROI 至少 64 个 valid pixel 才给 proximity 判断。
  • Proximity hysteresis：0.20 m 警告，0.25 m 清除；只是 operator aid。
  • Phase resynchronization：差动转向造成累计 phase offset，恢复直行时平滑收敛，不瞬间 reset。
  • Deadzone + clamp chain：输入层去 stick noise；mixer 层限制命令；driver 层相对 neutral ±70° 最终机械保护。
E典型故障、根因和防复发14 points
  • IMX219 FOV 随 sensor mode/分辨率改变：标定与运行 crop 不同会使 stereo geometry 失效；calibration 必须绑定 resolution + mode。
  • Cruise deadzone stutter：摇杆回到 deadzone 时从 live command 突然跳回 snapshot；用 override state + ramp。
  • dtoverlay 静默失败：config.txt section 错导致“zombie PWM”；验证实际 pin waveform，不只看 sysfs 无报错。
  • Zombie systemd service：旧 unit 删除后仍可能残留 enable/alias；检查 systemctl list-unit-files、symlink 和实际 ExecStart。
  • Motor startup jump：MIT command zero ≠ physical neutral；入模式前捕获并保持 current position。
  • Motor phase drift：差动频率与独立 idle reset 让两侧累积偏差；共享时间/显式 re-sync。
  • Motor 磁场污染 compass：mag yaw 不可信；用 gyro integration + 外部参考，或降低对绝对 yaw 的依赖。
  • Pi 5 H.264 假设错误：不存在期望硬编；使用 MJPEG/软件编码并按热状态降级。
  • Wi‑Fi interface name drift：profile 绑定稳定 identity，不依赖 wlan index。
  • Trigger double normalization：客户端已经归一化，服务端再次转换导致范围错误；接口 schema 写清 raw/normalized。
  • RGB/BGR channel flip：Picamera2 RGB888 与 PIL 已是 RGB，不要沿用 OpenCV BGR 假设。
  • GUI E-Stop 路径不完整：GUI 与 gamepad 必须调用同一安全 action，而不是复制两套 reset 逻辑。
  • 校园 Wi‑Fi session 过期：无头长期运行需要 local AP/可靠链路，不把开放网认证当控制依赖。
  • ARM64 native extension SIGSEGV：第三方 IDE 扩展崩溃与机器人程序分离；生产系统不依赖开发工具进程。

A控制模式、算法与数据结构8 points
  • Latched state machine：MANUAL、STATIC_PID、TRACKING 和 fault/STOP 状态显式锁存；噪声传感器不直接触发模式翻转。
  • 500 Hz PID：P on error、clamped integral anti-windup、derivative on measurement + 50 Hz 一阶低通；default Kp=4.8、Ki=0.01、Kd=0。
  • Quiet-hold Schmitt trigger：误差 <2° coast，>3° 恢复；减少噪声导致的 chatter/limit cycle。
  • Dead-zone feedforward：默认 5-count 补偿最小有效输出；不让 integral 单独穿越死区。
  • Watchdog：browser、serial、wireless、sensor 分层 timeout；失联转 coasted manual，通信恢复不自动 re-arm。
  • Priority queue：STOP 高于 telemetry poll、sine streaming 和普通命令；bounded FreeRTOS queue 防止 stale motion 累积。
  • Metronome/keep-alive：长时间运动按固定周期刷新，既满足 watchdog 又不修改固件安全语义。
  • Polarity abstraction + slew/co-activation：物理接线反向只在 driver config 处理；上下游统一使用 signed joint command。
BHall 传感、标定与角度数学implementation
  • AS5600L：12-bit、400 kHz I²C、地址 0x40（不要与 AS5600 的 0x36 混淆）。
  • 标定工具：5 s 静止噪声；neutral/+45/−45° 各 20 次；circular averaging 与 0/4095 unwrap；linear regression angle(raw)。
  • 结果：zero 4088.65 counts；scale −0.0907288°/count；R² 0.9999326；三点最大残差 0.43°；noise σ=2.18 counts → 约 0.20° noise-derived resolution。
  • Modular arithmetic：raw 跨 4095→0 时计算最短 circular difference；不能用普通减法制造巨大角度跳变。
  • Dataclass + JSON：保存 zero、scale、direction、noise、fit metrics 和版本；加载时验证字段与范围。
  • Zero-point averaging：多次样本平均降低随机噪声，但不能消除磁铁偏心/非线性等系统误差。
C双 MCU、协议与软件实现6 points
  • Commander/Driver topology：Commander 接 host serial/browser；Driver 直接接 AS5600L/H-bridge 并保留 500 Hz feedback loop。
  • Packed struct：二进制消息包含 version、type、message_id、mode、payload；双方固定宽度类型、packing 与 endian；用 size/static assertions 防 drift。
  • ACK matching：Commander 按 message_id 等待 Driver 应用层确认；无线 send callback 不等于命令已执行。
  • asyncio + aiohttp/WebSocket：同一 host process 并发 serial、HTTP 与 10–20 Hz browser telemetry；慢客户端不能阻塞 serial reader。
  • pyserial timeout + regex filter：串口读取有限等待，从混合 telemetry/ACK 流筛选对应 reply，绝不无限 block。
  • CONFIG block：实验频率、gains、range、timeout 集中；20 Hz sine setpoint 共享同一 phase，两个拮抗通道 anti-phase。

E实验数学、自动调参与 PIV 关联7 points
  • Strouhal：St=fA/U，明确 A 是 peak-to-peak 还是单边幅值；不能省略定义。
  • Empirical A(f)：若执行器振幅随频率变化，用实验曲线与迭代求解选择 command，不能把 A 当常数。
  • Phase averaging：按驱动相位对多个周期 bin/average，提取 coherent PIV structure。
  • Post-hoc phase recovery：没有可靠 trigger-in 时可从图像运动恢复相位，但精度和 failure mode 必须验证。
  • Lock-in criterion：用响应与驱动的 relative phase 是否稳定定量判定 lock-in。
  • Autotune：polarity/noise preflight → 可选 Tyreus-Luyben seed → coordinate twiddle Kp/Ki/Kd/deadband → 两次 0→+10→−10→0°。
  • Score：ITAE、overshoot、settling、steady-state error、limit-cycle、saturation；36 candidates / 72 sequences，cost 183.43→112.89（−38.5%），winning trial saturation 0%。
F典型硬件故障与工程教训11 points
  • GPIO3/D3 受 JTAG/boot 功能污染，产生伪 brake voltage；选安全 pin 并上电测波形。
  • boot-state glitch 在 setup() 前使 H-bridge energize；外部 pull-down/enable gate + firmware early LOW。
  • board kill 不是单因：启动高、back-EMF、USB backfeed 分别隔离验证。
  • reversed actuator wiring：polarity 只在 driver abstraction 修正。
  • open-loop lookup 无法修复 bang-bang plant；先承认没有稳定中间点，再改变控制/轨迹。
  • IPROPI resistor 未按 ADC 上限计算会损坏 ADC。
  • AS5600L 地址与 AS5600 不同；按实际 part number 查 datasheet。
  • 长 calibration hold 会超过 watchdog；keep-alive 或专用校准模式，但不关闭 safety。
  • XIAO 的 VBUS 不是任意 BAT input；按板卡 power-path 连接。
  • 无线且无 trigger-in 不适合精密电子 PIV sync；使用硬件触发或 post-hoc 方法并报告误差。
  • KiCad 工程不能只复制若干文件；用 project archive/rename，检查 symbol-footprint-net linkage。

A材料、结构和复阻抗core
  • 对称 sandwich：0.5 mm PLA base + 两侧 1 mm closed-cell acrylic foam VE core + 0.3 mm PET constraining layer；模块 100×76.5 mm。
  • 弯曲时 PET 限制 VE 自由伸缩，把 flexure 转为 core shear；rate-dependent shear 使每周期耗散随频率增加。
  • 单频 lock-in regression 从 θ(t)、T(t) 得到复幅值，K*=T̂/θ̂；实部 K′、虚部 K″。
  • elastic/dissipative fractions：K′/(K′+K″) 与 K″/(K′+K″)，用于比较组成而非只看总刚度。
  • 干态测试：±9°、0–5 Hz、ClearPath + ATI Mini-40、200 Hz DAQ；K′ 近似稳定，K″ 单调增长，hysteresis loop area 扩大。
B水洞、PIV 与任务级验证experiment
  • 四种 coverage：0%、16.7%、33.3%、66.7%；U=0.2 m/s，heave ±0.04 m，f=0.5–2 Hz（0.25 Hz step），St=0.2–0.8；每条件 3 次。
  • hydrodynamic load 200 Hz；NI/Simulink real-time heave command 4000 Hz；ATI Mini-40 测力。
  • 低 St 各构型推力接近；St>0.4 后分化；St=0.8 design c 0.51 N vs baseline 0.16 N（>200%）。
  • baseline efficiency 在 St≈0.3 约 20% 后下降；design c 约 10% plateau，并在 St>0.7 超过 baseline。
  • phase-resolved PIV：Photron Nova R3 + DaVis；0.5π design c 有更 coherent attached LEV 和 streamwise TEV；1.1π reversal 保持 chordwise vorticity continuity。
  • virtual mass：3 kg、St=0.8、3.8 s；design c displacement 0.617 m vs 0.213 m；peak acceleration 0.191 vs 0.039；terminal 0.291 vs 0.105 m/s。
  • mechanical low-pass：损耗抑制 higher-order parasitic bending，使 trailing edge 从 square-like distortion 回到 near-sinusoidal。
C论文边界与 RL 延伸boundary
  • 相位滞后在这里允许 stroke reversal 更平滑、改善 vortex timing；不能推广成“延迟越多越好”。
  • 仅单自由度 passive fin；virtual mass 是一维 carriage，不是物理自由游动；coverage 只有四级，未证明最优分布/厚度。
  • RL 设计：MuJoCo multi-segment fish，K(f)/B(f) 查表，Morison hydrodynamics，action=[frequency, amplitude]，6D state，λ-conditioned reward，SAC + curriculum。
  • 计划实验：CLD vs rigid convergence、Pareto frontier、±30% hydro error robustness、frequency schedule、sim-to-real；当前是设计/搭建，不是已验证结果。

  • 先跨五通道 start conversion，再逐通道 read，减少完全串行 conversion/read 的 channel skew。
  • 80 Hz = 12.5 ms period；用 Teensy micros() absolute schedule；记录 sequence、jitter、missed sample。
  • TTL rising edge 是共享 t=0；sample 0 已知安排在 12.5 ms；配对用 measured TTL-relative time，不用 keyboard/USB receive time。
  • Host–Teensy mapping 用 repeated round-trip minimum-RTT midpoint，只用于 absolute log metadata；不替代硬件同步。
  • 逐通道 baseline：Δpᵢ(t)=pᵢ(t)−mean baselineᵢ；common-mode subtraction 只在物理目标允许删除全局变化时使用。
  • Miniature PIV 采用 OV9281 global shutter 1280×800，避免快速粒子 rolling-shutter distortion；mini-camera FOV 必须映射到 NOVA R3 vector cells。
B模型架构、张量与软件实现14 points
  • Two-stage training：先 full-field autoencoder 学 flow manifold，再冻结/微调 decoder 学 sparse sensors→latent/dense field；两阶段 split 必须一致。
  • Cross-attention：每个 grid query 从 sensor tokens 选择相关信息；仅 5 tokens 会产生 rank≤5 bottleneck。
  • Learnable spatial tokens：作为额外 K/V 提高输出表示 rank，缓解 vorticity SSIM 卡在约 0.13 的结构瓶颈。
  • Sensor self-attention：先让不同传感器交换空间/相位信息，再供 grid query 读取。
  • Dual pathway：PIV patches 与 scalar pressure 各自 encoder，再 cross-modal fuse，避免异构尺度互相污染。
  • Shared-weight encoder：五个同类型 patch/sensor 复用权重，减少参数并保持 permutation consistency。
  • Temporal channel stacking：把多个 time steps 堆为 channels，让 2D CNN 获取短时上下文，不引入 LSTM。
  • Ensemble heads：不同 decoder/model 预测分歧形成 uncertainty map，为 active learning 选 case。
  • Config flags + W&B：同一代码运行 pretrained/e2e 2×2 ablation；run name、seed、dataset version、config 可查询。
  • einsum / reshape：处理 batch×sensor×time×channel×height×width，不用 Python nested loop；每次 reshape 明确维度语义。
  • Frozen perceptual module：用预训练 encoder feature 做 loss，但 requires_grad=False 且 eval mode。
  • .mat I/O：scipy 读取后显式检查 MATLAB column-major / dimension order / transpose / units。
C物理量、损失与评估10 points
  • Vorticity：ω=∂v/∂x−∂u/∂y，有限差分必须带实际 dx/dy 与坐标方向。
  • Fourier position encoding：multi-frequency sin/cos 帮助网络表示尖锐 vortex boundary，缓解 MLP spectral bias。
  • Sobel gradient loss：惩罚边缘/剪切层模糊；vorticity-weighted MSE 用 |ω| 让 vortex core 而非 freestream 主导。
  • Divergence penalty：∂u/∂x+∂v/∂y≈0 作为 incompressibility regularizer；边界/噪声区域需 mask。
  • SSIM 衡量局部结构，不代替量纲误差；同时报告 velocity、vorticity、peak/core metrics。
  • Phase average：去掉第一周期 transient，使用后两周期提取 coherent target。
  • Reynolds decomposition：预测 fluctuation 而非让模型容量浪费在 static mean；输出再加回 mean。
  • Non-dimensionalization：u/U、Cp、x/c 使不同 St/geometry 可比较；train statistics 不能用 test。
  • POD 只作 diagnostic：比较预测与真实 modal energy spectrum，不作为主重建方法。
  • Active learning：Latin Hypercube 初始覆盖 St/spacing/chord；ensemble uncertainty 选下一批昂贵实验。
D数据泄漏与失败模式9 points
  • autoencoder pretrain 若包含 test flow，Stage 2 会变成 lookup；两阶段都必须 case-level 隔离。
  • 5-token cross-attention rank bottleneck 是结构问题，继续调 learning rate 无法解决。
  • full-field encoder 与 patch encoder shape 不兼容，不能声称直接 transfer weights。
  • T=1 loader 曾静默变成 6 channels 而非预期 3；assert tensor shape 与 config。
  • 约 40 个 phase-averaged sample 使用 batch 32 接近 full-batch，随机性低且易 overfit。
  • phase angle 若真实机器人不可观测，就是 oracle leakage；训练/部署输入必须一致。
  • 第一振荡周期含 startup transient，不能混入 steady phase average。
  • 单一 constant-St wake 自相似，随机 frame split 会制造虚假泛化。
  • freestream pixel 占多数会抬高全场指标；按 vortex/ROI/case 分层报告。

A视频定位与多模态算法12 points
  • Contact sheet：把完整动作时序排在一张图中，减少数十次单帧调用；frame number/phase label 保持可追溯。
  • Frame difference：灰度/裁剪后相邻帧绝对差得到 motion score；Gaussian smoothing 合并噪声峰。
  • Audio onset：16 kHz mono waveform，spectral onset strength + bandpass 定位击球 transient。
  • Multi-signal fusion：audio peak 必须在相近时间有视觉 motion 支持，过滤评论、掌声、邻场。
  • Minimum inter-peak gap：利用单次击球的物理最短间隔抑制回声/双检。
  • Coarse-to-fine：计算先从 30–90 min 缩到 clip/30-frame window，LLM 只做语义精判。
  • Model tiering：便宜模型先分类/粗判，昂贵推理模型只处理少量高价值候选；成本差是配置事实，不能永久硬编码某型号。
  • Fixed-phase FSM：准备→引拍→击球→随挥严格单调；LLM 非单调 frame 经过 validation/reorder/reject。
  • Weighted sampling：contact 附近与阶段边界采样密，静止区稀疏；有限 frame budget 不均匀浪费。
  • RAG-style injection：按阶段/错误检索教练知识；模型必须用视频 evidence，再选择根因与 drill。
  • Three-stage extraction：中文教练视频 → Whisper/SRT transcript → segment/topic extraction → 结构化动作知识。
  • Classification hierarchy + sanity check：shot type→phase→error；输出前检查 frame range、顺序、字段和 evidence consistency。
B后端、数据结构与实现方法14 points
  • 现行资料：FastAPI + SQLAlchemy + PostgreSQL/SQLite + JWT；旧 Deck 含 Flask 原型知识。面试时按当前版本说，原型迁移可作为演进故事。
  • Modular backend：route/controller、auth、service、model client、repository 与 app initialization 分离。
  • Central API client singleton/factory：认证、timeout、retry、model ID 和 backend switching 集中；不在各模块硬编码。
  • Environment-variable switching：dev/prod 使用同一代码，通过 config 选择 provider/database/storage；secret 不入库。
  • SDK migration：adapter 保留 prompt/schema 逻辑，更换 provider client；全仓搜索旧 import/model string。
  • Pydantic schema：API/LLM response 先 validate，再 model_dump() 给下游；frontend/backend 共用版本化字段契约。
  • Fence stripping：兼容 LLM 把 JSON 包在 Markdown fence；仍必须 schema validation，不能只 json.loads。
  • OpenCV frame-exact extraction：按 native fps 与 frame index seek/verify，避免转码后编号与播放器时间轴不一致。
  • ffmpeg subprocess：subprocess.run(..., check=True, capture_output=True) 抽 16 kHz mono audio 与 2.5 s clip；保存 stderr。
  • Whisper local：教练知识转录可本地完成，避免把私有素材发外部。
  • UUID job/session：每用户/每分析独立目录与记录，避免并发文件名冲突；cleanup 按 owner/job scope。
  • dotenv relative path：从明确 project/config path 加载，不依赖启动 cwd。
  • Wizard UI / PWA：多阶段桌面工具可用 PyQt wizard；产品前端用 responsive PWA、manifest、service worker。
  • Headless server：使用 opencv-python-headless 避免 X11/Qt import；production workers 处理并发，但长任务应转 job queue。

D数学与信号处理细节7 points
  • Inter-frame absolute difference 量化运动量，不等于 pose/biomechanics；ROI、光照变化和 camera motion 会干扰。
  • Gaussian smoothing 在 motion score 上合并同一次动作附近多个噪声峰；kernel/σ 决定时间分辨率。
  • Spectral onset strength 找音频 transient；bandpass 隔离击球频段但需真实数据验证。
  • Minimum peak distance 注入击球物理约束，抑制 echo/double detection。

  • 评估分层：phase/evidence accuracy、error 与 coach agreement、用户训练后 improvement；功能测试不等于教学有效性。

06 · CROSS-PROJECT CORE

机器人项目共通知识

五个项目反复出现的工程原则

状态必须带时间

value、timestamp、sequence、valid、source、error 是一个整体。旧值存在不代表当前可用。

实时环留在硬件附近

500 Hz VCA PID、200 Hz motor trajectory 不经过浏览器、Wi‑Fi 或慢视觉。

队列必须有界

latest-frame、command mailbox、recorder queue、log ring buffer 都必须定义容量与 drop policy。

安全优先于模式

E-Stop、armed、fault latch、mechanical limit 在所有普通模式之外统一门控。

共同时间基优先

硬件 trigger 优于软件 start；monotonic clock 用于 dt/timeout，epoch 用于人类日志。

标定不等于验证

fit residual、RMS 和 R² 说明模型拟合；独立工况才说明 accuracy/generalization。

接口表达语义

raw vs normalized、absolute vs incremental、command vs event、source ownership 都必须写进 schema。

失败数据也要保存

run_id、config、commit、partial artifact、excluded reason 让实验和现场 bug 可复现。

指标与任务对齐

flow MSE、stereo RMS、composite PID cost、功能测试数量都不能代替最终任务指标。
